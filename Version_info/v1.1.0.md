# Version 1.1.0 - 本人確認機能追加

**リリース日**: 2026-01-15

---

## 概要

本人確認申請機能（ユーザー向け）と審査機能（管理者向け）を追加。

---

## 追加機能

### 1. 本人確認申請（ユーザー向け）

| 項目 | 内容 |
|------|------|
| URL | `/monotal/identity-verification/` |
| 機能 | 顔写真、身分証（表面）、身分証（裏面/厚み）の3枚をアップロードして本人確認を申請 |
| ステータス表示 | 審査中、承認済み、却下の状態を表示 |

### 2. 本人確認審査（管理者向け）

| 項目 | 内容 |
|------|------|
| 一覧URL | `/monotal/admin/verifications/` |
| 詳細URL | `/monotal/admin/verifications/<id>/` |
| 機能 | 未審査の申請を古い順に表示、画像確認、承認/却下 |
| 権限 | `is_staff=True` のユーザーのみアクセス可 |

---

## 管理者画面URL規則

管理者向け画面のURLは `/monotal/admin/` で始めること。

| 種別 | URLパターン | 例 |
|------|-------------|-----|
| ユーザー向け | `/monotal/<機能名>/` | `/monotal/identity-verification/` |
| 管理者向け | `/monotal/admin/<機能名>/` | `/monotal/admin/verifications/` |

### 理由

- Django標準の `/admin/` と区別するため
- 管理者画面であることを明確にするため
- 権限チェックの対象を識別しやすくするため

## ステータス定義

### IdentityVerificationStatus

| ID | 名称 | 説明 |
|----|------|------|
| 0 | 未確認 | 申請後、審査待ち |
| 1 | 承認 | 管理者が承認 |
| 2 | 却下 | 管理者が却下 |

### 承認時の動作

- `IdentityVerification.identity_verification_status_id` → 1
- `IdentityVerification.approval_datetime` → 現在日時
- `User.user_status` → UserStatus(id=2)（承認済みユーザー）

### 本人確認完了の判定

本人確認画面では `User.user_status_id == 2` でユーザーの本人確認完了を判定する。

## ユーザーステータスの扱い方（外部キー参照）

### Userモデルの定義

```python
class User(AbstractBaseUser, PermissionsMixin):
    user_status = models.ForeignKey(
        UserStatus,
        on_delete=models.PROTECT,
        db_column='user_status_id'
    )
```

### 注意点

`user_status`はForeignKeyのため、更新時は**整数ではなくオブジェクト**を設定する必要がある。

```python
# ❌ 間違い（FOREIGN KEY constraint failedエラー）
user.user_status_id = 2
user.save()

# ✅ 正しい
user_status = UserStatus.objects.get(user_status_id=2)
user.user_status = user_status
user.save()
```

### 参照時

読み取りは `user_status_id` で整数値を取得可能。

```python
# ステータスIDの取得
if request.user.user_status_id == 2:
    # 承認済みユーザー
```
